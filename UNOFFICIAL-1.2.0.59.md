# IV-SDK .NET 1.9.1 - Unofficial Beta for GTA IV 1.2.0.59

This branch is an **unofficial** fork of [IV-SDK .NET](https://github.com/ClonkAndre/IV-SDK-DotNet) by
[ItsClonkAndre](https://github.com/ClonkAndre), which is built on [IV-SDK](https://github.com/Zolika1351/iv-sdk) by
[Zolika1351](https://github.com/Zolika1351). It makes IV-SDK .NET 1.9.1 run on **GTA IV 1.2.0.59 (Complete Edition)**.

- Fork maintained by [bassisthip63-ui](https://github.com/bassisthip63-ui). Research and code changes were done with the
  help of Claude (an AI model by Anthropic).
- **Not supported by ItsClonkAndre.** Please report problems with this build to this fork's
  [Issues](https://github.com/bassisthip63-ui/IV-SDK-DotNet/issues) page.
- For GTA IV 1.0.7.0 and 1.0.8.0, use the official IV-SDK .NET. This build does **not** work on those versions.
- Licence: GNU General Public License v3, the same as IV-SDK .NET and IV-SDK (see [LICENSE](LICENSE)).
  The complete source code of everything this fork distributes is in this repository.

Status: **Beta.** Tested on 1.2.0.59 with LibertyTweaks 1.7, the ScriptHookDotNet port for IV-SDK .NET and a range of
ScriptHookDotNet and IV-SDK .NET scripts. Expect rough edges; see "Known limits" below.

## Install (players)

1. Install the **official** IV-SDK .NET 1.9.1 into your GTA IV 1.2.0.59 folder, following its
   [Installation Guide](https://github.com/ClonkAndre/IV-SDK-DotNet/blob/main/Documentation/Installation.md).
2. Back up the files you are about to replace.
3. From this fork's release, copy:
   - `IVSDKDotNetWrapper.dll` over the one next to `IVSDKDotNet.asi`
   - `12059.ini` into the `IVSDK` folder (next to `1070.ini` and `1080.ini`)
4. Start the game. The first lines of `IVSDKDotNet.log` should include
   `UNOFFICIAL BETA build for GTA IV 1.2.0.59`.

Use this DLL only on 1.2.0.59. To go back, restore the official `IVSDKDotNetWrapper.dll`.
If IV-SDK .NET's update notice offers a newer official version, note that installing it replaces this build.

## What was changed (all on 2026-10-27, by bassisthip63-ui)

Every changed spot in the source is marked with a dated comment. In short:

| Area | File(s) | Change |
|---|---|---|
| Native calls | `IVSDKDotNet/IVSDK/CTheScripts.h` | On 1.2.0.59 the game's `FindNativeAddress` takes the native hash on the stack and removes it with `ret 4`; 1.0.7.0/1.0.8.0 take it in `ESI`. Without this every native call looks up the wrong hash and unbalances the stack. Checked at run time. |
| Menu settings | `IVSDKDotNetWrapper/IVMenuManager.cpp`, `IVSDKDotNet/IVSDK/NewAddressSet.h` | `IVMenuManager.GetSetting/SetSetting` had addresses for 1.0.7.0/1.0.8.0 only and read address 0 on any other version. Added the 1.2.0.59 address (0xD60C60) and a three-version `GetRef` overload. Checked at run time. |
| Struct layouts | `IVSDKDotNet/IVSDK/IVSDK12059.h` (new), `CVehicle.h`, `CPed.h`, `CPlayerInfo.h`, `IVSDK.h` | 1.2.0.59 moved fields of `CVehicle` (everything from 0x260 on: -0x50), `CPed` (ShootRate/Accuracy: -0x18; 0x3A8 on: -0x10) and `CPlayerInfo` (Stamina: +0x10; 0x4BC on: +0xC). The define `IVSDK_GTAIV_12059` in `IVSDK12059.h` selects these layouts. `static_assert` checks for every moved field are included, so a wrong layout fails to compile. |
| Offsets | `IVSDKDotNet/Memory Offset Config Files/IVSDK/12059.ini` (new) | The 1.2.0.59 offset file. Generated by matching code and data between the 1.0.8.0 and 1.2.0.59 executables, then checked by hand in the disassembly where needed. |
| Log line | `IVSDKDotNetWrapper/CLRBridge.cpp` | Writes "UNOFFICIAL BETA build for GTA IV 1.2.0.59 ..." to the log, so every log shows this is not an official build. |
| README | `README.md`, this file | Notices about the fork. |

How the 1.2.0.59 layouts were found: by comparing the game's own native functions between the two executables (about
280 field accesses, about 60 for CVehicle, 30 for CPed and 20 for CPlayerInfo, none disagreeing), plus checks by hand.

## Known limits

- **19 functions are not yet found in 1.2.0.59** and are commented out in `12059.ini`. IV-SDK only looks them up when a
  script calls them; a script that does gets IV-SDK's "address not found" message and the game closes. They are:
  `CDrawRectDC`, `CFont::SetScale`, `CFont::SetColor`, `CGarage::TidyUpGarageClose`, `CIplStore::SetIfIplIsRequired`,
  `CIplStore::SetIfIplIsRequiredReducedBB`, `CPhysical::_ProcessWater`, `CPickups::Reset`, `CRadar::DrawFrameFront`,
  `CRadar::DrawFrameBack`, `CRestart::Save/Load`, `CTaskComplexInWater`, `CTheScripts::AddToBuildingSwapArray`,
  `CTheScripts::Save`, `CTheZones::Save/Load/IsPointInZone`. ScriptHookDotNet scripts do not use them.
- Kept at their 1.0.8.0 offsets because they are not verified on 1.2.0.59: `CPlayerInfo::m_pPlayerPed2` and the six
  `m_nLast...Time` timers, and the internal layout of the ped weapon data (`CPed + 0x2B0`).
- Two `12059.ini` entries are placeholders pointing at unused memory: `CMenuManager::m_fSaturation` and
  `CRestart::NumberOfSafehouses`.
- `fiFile` in IV-SDK uses hard-coded 1.0.8.0 addresses; `fiDevice` has one extra virtual function in 1.2.0.59, so
  calls through its later vtable slots are off by one. Both are rarely used.
- Other classes (camera extras, model info, garages and so on) were not examined for layout changes.
- Mods that use `MemoryAccess.GetAbsoluteAddress(address1070, address1080)` themselves get nothing on 1.2.0.59; those
  addresses are in the mod, not in IV-SDK .NET.

## Build (developers)

Only `IVSDKDotNetWrapper.dll` differs from the official 1.9.1 release, so only that project needs building.

1. Install **Visual Studio 2022** (Community is free) with the workload **Desktop development with C++**, plus the
   individual components **C++/CLI support for v143 build tools** and **.NET Framework 4.7.2 targeting pack**.
2. The wrapper includes `d3dx9.h`, which comes from the legacy **DirectX SDK (June 2010)**. If the build reports
   `d3dx9.h` not found, install that SDK, then in the IVSDKDotNetWrapper project's properties (Release, Win32) under
   *VC++ Directories* add `$(DXSDK_DIR)Include` to *Include Directories* and `$(DXSDK_DIR)Lib\x86` to
   *Library Directories*.
3. Open `IVSDKDotNet.sln`, choose **Release** and **x86**, right-click **IVSDKDotNetWrapper** and choose **Build**.
4. The DLL is in `Release\IVSDKDotNetWrapper.dll` (or the project's output folder shown in the build log).

To build the normal 1.0.7.0/1.0.8.0 version from this branch instead, comment out `#define IVSDK_GTAIV_12059` in
`IVSDKDotNet/IVSDK/IVSDK12059.h`.
